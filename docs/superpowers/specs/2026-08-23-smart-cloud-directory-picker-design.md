# Knowledge Workbench 智能云端目录选择器设计

- 状态：交互、数据安全与异常设计已批准；书面规格已自审，待用户复核
- 日期：2026-08-23
- 适用产品：Knowledge Workbench for Obsidian
- 目标版本：`v0.1.1`
- 前置规格：`2026-08-11-knowledge-workbench-ui-i18n-design.md`
- 替代范围：仅替代前置规格第 7 节中“首次必须手工提供非根起点”的交互，不改变扫描、核验、OAuth、TXT 导入或 acceptance 构建的安全语义

## 1. 背景与结论

`v0.1.0` 已提供“浏览网盘目录”按钮、会话内模糊搜索和显式“搜索更多目录”，但选择器在打开前仍要求一个合法非根 `initialRoot`。当路径输入为空时，controller 会先执行 `normalizeCatalogScanRoot` 并拒绝打开选择器。因此首次使用或 Obsidian 重启后，用户仍要手工输入完整云端路径，“浏览”没有真正成为主要入口。

本阶段采用已批准的“智能目录选择器”方案：

1. 打开选择器时合并最近使用、TXT 分类提示和当前会话缓存，且发送零次百度请求；
2. 用户可以直接模糊搜索并点击已知完整路径；
3. TXT 只提供未核验名称提示，不能冒充准确云端路径；
4. 名称存在歧义时，用户可显式点击“在网盘中定位同名目录”，查看预算并确认一次受限只读查找；
5. 选中目录只回填路径，不自动扫描或核验；
6. 原有手工输入保留在“高级”折叠区，作为恢复和专家备用入口。

该方案不把 PDF 下载到本机，不索引 PDF 正文，不在后台访问百度，也不允许把 `/` 直接用于扫描或核验。

## 2. 用户目标与成功标准

完成后，用户应当能够：

1. 在路径为空时点击“选择目录”并看到可用候选，而不是收到无上下文的路径错误；
2. 通过“最近”“TXT 分类”“已缓存”三个来源搜索目录，不必记忆或手输完整路径；
3. 看到每个结果的显示名称、完整父路径、来源和核验状态；
4. 在同名目录之间依据完整父路径作出选择；
5. 对仅有名称的 TXT 提示执行一次明确确认的受限云端定位；
6. 在重启 Obsidian 后继续使用最近 10 条目录；
7. 清空最近目录，而不影响 TXT 候选、云端核验结果或 OAuth 凭据；
8. 使用键盘完成搜索、移动、选择、取消并恢复焦点；
9. 在网络、授权、预算、取消或持久化失败时继续使用不受影响的本地候选。

以下是验收级成功标准：

- 打开选择器、切换来源、输入搜索词和选择本地结果的百度列表请求数均为 `0`；
- 只有显式点击“在网盘中定位同名目录”并通过确认后，定位器才可调用百度列表端口；
- 选择结果只更新当前 UI 的路径草稿，不调用扫描或核验服务；
- `/` 永远不能成为可选结果，也不能被传给现有扫描或核验入口；
- acceptance 构建继续没有 OAuth、SecretStorage、百度列表、云端定位或外部目录写入能力。

## 3. 非目标

本阶段不会：

- 自动扫描百度网盘、启动时访问百度或定时刷新目录；
- 在用户逐键输入时发送百度请求；
- 下载、解析、OCR、摘要或索引 PDF 正文；
- 修改、上传、移动、重命名或删除网盘文件；
- 实现无预算的全网盘递归搜索；
- 使用拼音、语义向量、AI 或错别字模型匹配目录；
- 自动认定 TXT 根名称就是准确云端路径；
- 自动选择同名目录或自动修复云端路径冲突；
- 自动开始扫描、分类核验或恢复已有批次；
- 将 AppKey、SecretKey、OAuth Token、授权码或原始运行时错误写入普通设置、历史、日志或界面；
- 改变已有目录记录、核验覆盖层、checkpoint、活动 manifest 或 PDF 搜索的数据语义。

## 4. 交互设计

### 4.1 设置页入口

“云端目录”和“云端核验”中的路径编辑区统一为：

1. **当前目录卡片**：显示名称、完整路径和最近一次状态；没有选择时显示明确空状态；
2. **选择目录**：主要动作，路径为空时仍可使用；
3. **开始只读扫描／开始核验**：保持原按钮和原确认门，未选择合法非根路径时禁用；
4. **高级：手动输入路径**：折叠备用入口，保留现有校验动作与说明。

“选择目录”不得隐式验证、扫描、核验或保存凭据。

### 4.2 选择器布局

选择器包含：

- 模糊搜索框，打开后自动聚焦；
- 来源筛选：“最近”“TXT 分类”“已缓存”；默认合并显示；
- 结果列表；
- 当前选择摘要；
- “在网盘中定位同名目录”；
- “清空最近目录”；
- “取消”和“使用所选目录”。

结果行固定显示：

- 目录名称；
- 完整路径或“名称未核验”；
- 来源标签；
- `已核验路径`、`以前使用`、`会话缓存`、`TXT 提示` 或 `冲突` 状态；
- 冲突原因或下一步动作。

TXT 提示没有准确完整路径时，不显示为可选择结果；其主要动作是“在网盘中定位同名目录”。

### 4.3 选择行为

“使用所选目录”执行以下动作：

1. 再次规范化和校验准确完整路径；
2. 将路径回填到调用方的会话草稿；
3. 更新当前目录卡片；
4. 尝试在普通设置存储中更新最近目录；保存失败不阻止返回本次选择，只显示固定安全提示；
5. 关闭 Modal 并恢复“选择目录”按钮焦点。

它不得调用 `startScan`、`startLargeVerification`、恢复批次、OAuth 或百度列表端口。用户必须在外层页面另行点击扫描或核验按钮并通过既有确认框。

## 5. 候选数据模型

统一候选使用有限判别联合，而不是让 UI 根据缺失字段猜测状态：

```ts
type CloudDirectoryCandidate =
  | Readonly<{
      kind: "exact";
      path: string;
      filename: string;
      source: "recent" | "session-cache" | "cloud-locator";
      pathState: "previously-used" | "session-verified";
      cloudFsId?: string;
    }>
  | Readonly<{
      kind: "name-hint";
      filename: string;
      source: "txt-group";
      catalogGroupKey: string;
    }>
  | Readonly<{
      kind: "conflict";
      filename: string;
      path: string;
      source: "cloud-locator";
      reason: "same-path-different-identity";
    }>;
```

规则：

- `exact` 才能成为选择结果；
- `name-hint` 只能用于本地搜索和发起定位；
- `conflict` 必须禁用，不能通过手工 DOM 操作绕过；
- UI 不显示 `cloudFsId`，它只用于同一次定位中的身份校验；
- 持久化的最近目录不保存 `cloudFsId`，避免把一次云端身份快照伪装成永久有效状态。

## 6. 候选来源与合并

### 6.1 最近使用

普通 `PluginSettings` 新增有限版本化字段，最多保存 10 条：

```ts
interface RecentCloudDirectory {
  readonly path: string;
  readonly filename: string;
  readonly lastUsedAt: string;
}
```

约束：

- 每次写入前规范化路径并拒绝 `/`；
- 按规范化路径去重；
- 最近使用移到首位，超过 10 条删除最旧项；
- `lastUsedAt` 必须是严格 UTC 时间字符串，仅用于稳定排序；
- 设置解码失败时丢弃整个无效 recent 字段，不能阻止插件加载；
- “清空最近目录”只清除此字段；
- 不写入 SecretStorage、历史、操作记录、核验 checkpoint 或 TXT manifest。

用户已明确允许保存最近路径。设置页必须同时说明路径将保存在本机，并提供一键清空。

### 6.2 TXT 分类提示

从活动大型目录的 group 投影生成名称提示：

- `txt-root-items` 不作为云端目录提示；
- 一级 group 的显示名称和稳定 group key 可以进入本地候选；
- TXT 根名称和 group 名称不得直接拼接成可扫描的绝对云端路径；
- TXT 提示必须标记“未核验名称提示”；
- 定位成功后返回新的 `exact` 候选，但不修改 TXT 导入记录或 group key。

### 6.3 当前会话缓存

复用并收紧现有目录发现缓存：

- 仅保留当前插件进程中已经完整验证并提交的目录页；
- `dispose`、断开连接或显式清除时释放；
- 不进入普通设置或 SecretStorage；
- 搜索输入只读取该缓存，不触发列表端口。

### 6.4 合并和排序

候选先按规范化完整路径去重，再按来源和模糊分数排序：

1. 当前已选路径；
2. 最近使用；
3. 会话已核验缓存；
4. TXT 名称提示；
5. 相同层级按完整名称、前缀、名称包含、路径包含的现有稳定分数；
6. 分数相同按规范化路径或稳定 group key 排序。

不同来源指向同一完整路径时合并为一个结果，并显示多个来源标签。若同一完整路径在一次云端定位中出现不同百度目录 ID，则生成唯一 `conflict`，不选择任一身份。

## 7. 显式云端同名定位

### 7.1 权限边界

定位器是 normal 构建的独立可选能力。打开选择器不会调用它。仅当用户：

1. 选择一个 `name-hint` 或输入非空名称；
2. 点击“在网盘中定位同名目录”；
3. 查看查找词、入口和固定预算；
4. 点击最终确认；

定位器才可调用现有只读 `BaiduCatalogSourcePort.listDirectory`。

定位器可以从 `/` 读取目录元数据，但 `/` 只允许作为此专用定位操作的遍历入口：

- `/` 不进入候选列表；
- `/` 不写入最近目录；
- `/` 不返回给调用方；
- `/` 不允许传给扫描或核验服务；
- 该例外不得通过共享路径校验放宽现有 `normalizeCatalogScanRoot`。

### 7.2 固定预算与遍历

单次定位采用页原子、广度优先、只读遍历：

- 最多提交 500 个目录；
- 最多开始 50 次列表请求；
- 最长 120,000 毫秒；
- 单页沿用百度列表适配器的固定分页上限；
- 目录名称在本地按现有确定性规则匹配；
- PDF 和其他文件不进入结果，但仍必须通过响应解码和身份校验；
- 达到预算、取消或超时后不提交正在处理的半页；
- 已完整提交的匹配结果在本次 Modal 中继续可用；
- 不自动继续、重试或扩大预算。

定位返回摘要必须包含：状态、停止原因、目录数、匹配数、列表请求数和耗时。UI 不把暂停状态称为“完成”。

### 7.3 身份和路径校验

每个响应条目继续验证：

- 绝对路径规范化后与原值一致；
- 文件名等于路径末段；
- `fsId` 格式有效；
- 直接父目录符合当前列表请求；
- 同一运行内路径和 `fsId` 双向唯一；
- 目录条目的大小等既有 Baidu 响应约束有效。

同名但父目录不同的结果全部展示完整路径。相同完整路径对应不同 `fsId` 时，定位器返回冲突而不是任意挑选。若百度 API 无法通过路径唯一寻址该对象，插件要求用户先在百度网盘处理冲突。

## 8. 组件和接口边界

定向新增或调整以下模块：

- `catalog/cloud-directory-candidates.ts`：纯函数合并、去重、排序和冲突投影；
- `catalog/cloud-directory-locator.ts`：专用根入口、固定预算、页原子 BFS 和摘要；
- `settings/plugin-settings.ts` 或现有设置 codec：最近目录的 schema、迁移和 10 条上限；
- `ui/cloud-directory-picker.ts`：来源筛选、结果列表、定位确认、键盘和选择；
- `ui/settings-sections.ts`：当前目录卡片、主要“选择目录”按钮和高级手工输入；
- `ui/workbench-controller.ts`：取得本地候选、发起定位、回填路径和更新最近目录；
- `runtime/runtime-composition.ts` 与 normal composition：仅向 normal 图注入定位能力；
- `i18n/workbench-i18n.ts`：新增状态、来源、确认、预算、冲突、清空和安全错误键。

Modal 不直接读写 settings、SecretStorage 或百度端口。Controller 不实现模糊评分或 BFS。Locator 不依赖 DOM、Obsidian Modal、PluginSettings 或 TXT runtime。

接口边界采用：

```ts
interface CloudDirectoryCandidateRuntime {
  snapshot(): readonly CloudDirectoryCandidate[];
  remember(path: string): Promise<void>;
  clearRecent(): Promise<void>;
}

interface CloudDirectoryLocatorRuntime {
  locateByName(
    name: string,
    signal?: AbortSignal,
  ): Promise<CloudDirectoryLocatorSummary>;
}
```

生产层仍复用同一个 Baidu source 实例和请求许可边界，不创建第二套 OAuth、Token refresh 或 list adapter。

## 9. 生命周期、错误与恢复

### 9.1 取消和迟到响应

- 关闭 Modal、按 Escape、插件卸载或连接撤销都会 abort 当前定位；
- 所有进度、结果、错误、最近目录写入和 DOM 更新前检查当前 generation 与 signal；
- 迟到响应不得复活 Modal、覆盖新搜索、改变选择或写入最近目录；
- promise 只 settle 一次，关闭后清空输入和会话敏感 DOM；
- 焦点恢复到打开选择器的按钮。

### 9.2 固定安全错误

界面只显示有限错误状态：

- 未连接百度；
- 定位被取消；
- 达到目录、请求或时间上限；
- 百度响应无效；
- 目录身份冲突；
- 最近目录保存失败；
- 功能在当前构建中不可用。

不得渲染原始 `Error.message`、响应正文、Token、凭据、授权码、真实本机路径或堆栈。保存最近目录失败只降级为本次会话可用，不撤销已经选择的目录。

### 9.3 陈旧最近路径

最近路径只表示“以前使用”，不声称云端仍存在。实际扫描或核验若返回不存在／无权限，沿用原有安全错误并保留最近项，直到用户主动清空或选择新的准确路径。本阶段不在后台验证最近项。

## 10. 键盘和无障碍

- 打开时焦点进入搜索框；
- Tab 顺序为搜索、来源筛选、结果、定位动作、清空、取消、使用；
- 上／下方向键在可选结果间移动；
- Enter 选择当前结果；
- Escape 取消并恢复 opener 焦点；
- 选中项使用 `aria-selected`，来源筛选使用合适的 tab 或 pressed 语义；
- 状态和定位进度使用 `role="status"` 与 `aria-live="polite"`；
- 冲突结果使用可读说明，不只依赖颜色或禁用态；
- 长路径允许换行，并在窄窗口中保持主要操作可达；
- 中文和英文键集合、插值参数和 ARIA 文案保持一致。

## 11. 测试与验收

### 11.1 单元测试

- 最近目录 codec、无效字段迁移、规范化、去重、排序和 10 条上限；
- 候选三来源合并、稳定模糊排序和来源标签；
- TXT 提示不可选择；
- 同名不同路径全部保留；
- 相同路径不同 `fsId` 生成冲突；
- 定位 BFS、页原子提交、固定预算、精确请求计数、取消和时间边界；
- `/` 只可作为 locator 内部入口，永不成为返回值。

### 11.2 UI 测试

- 空路径可以打开选择器；
- 打开、搜索、筛选和本地选择的百度调用为零；
- 最近、TXT、缓存状态和完整路径正确显示；
- 清空最近只调用对应设置动作；
- 定位需要两步显式动作，确认前调用为零；
- 选择只回填路径，不启动扫描或核验；
- 键盘导航、焦点恢复、Escape、窄宽和长路径；
- 保存失败、未授权、部分结果和冲突使用固定安全文案；
- dispose／rerender／取消后的迟到异步结果不复活 DOM。

### 11.3 集成和组合测试

- normal composition 复用现有 Baidu source，并只暴露一个 locator factory；
- offline／disabled／acceptance composition 不暴露 locator；
- locator 根入口不能泄漏到 scan 或 large verification；
- settings 与 workbench verification 两个宿主共享同一选择器语义；
- locale 切换不清空查询、来源筛选或当前选择；
- 插件重启后最近目录恢复，SecretStorage 与核验 checkpoint 不变。

### 11.4 回归门禁

- 完整串行测试；
- TypeScript、ESLint、normal build 和 acceptance build；
- 100,000 条本地目录与 70,000 条混合目录性能门禁保持现有阈值；
- 包装扫描证明 acceptance bundle 不包含 locator、OAuth、SecretStorage 或 list 能力；
- 所有云端定位测试使用合成 source，不发真实百度请求；
- 真实网盘人工验收必须另行取得新的明确授权，并限制为不敏感目录元数据。

## 12. 迁移与发布

- 设置 schema 以向后兼容方式新增空的最近目录列表；现有安装不自动生成或猜测路径；
- `v0.1.0` 的 session-only 路径不迁移，因为它从未持久化；
- 首次升级打开选择器时，用户看到 TXT 提示和当前会话缓存；没有准确路径时可显式发起定位；
- 旧“浏览网盘目录”按钮改名为“选择目录”，原手工输入移入高级区；
- 发布说明明确最近路径保存在插件普通设置中，并可清空；
- README 的“默认不扫描 `/`”调整为更精确的边界：扫描和核验继续拒绝 `/`，只有显式同名定位可在固定预算内读取根目录元数据。

## 13. 已批准决策摘要

- 采用方案 1“智能目录选择器”；
- 默认来源是本地最近、TXT 提示和会话缓存；
- 允许本机保存最多 10 条最近完整路径并一键清空；
