# 百度网盘云端书库目录设计

- 状态：架构方案已获用户确认；2026-08-05 已改为官方 `redirect_uri=oob`；授权页不提供目录选择器，用户已明确接受全盘网盘读写 OAuth 范围，但产品代码仍限制为只读目录列表
- 日期：2026-08-05
- 工作名称：Cloud Catalog / 云端书库
- 适用产品：Knowledge Workbench for Obsidian
- 首期平台：macOS 上的 Obsidian Desktop

## 1. 背景

用户约有 3.2 TB PDF 保存在自己的百度网盘中，本地硬盘不足以容纳全部原文件。当前没有可直接导入的 TXT、CSV 或 Excel 目录，只有百度网盘客户端中的文件夹树。

用户选择的首要目标是：在 Obsidian 中知道自己有哪些书，并能快速定位百度网盘中的原文件。首期不要求全库 PDF 正文检索、OCR 或 AI 问答。

因此，本功能不能把百度网盘变成 Obsidian Vault，也不能把每份 PDF 转成 Markdown。它应将“云端原文件”“本地派生目录”和“用户知识笔记”分开管理。

## 2. 目标

首期成功时，用户可以：

1. 通过百度官方 OAuth 授权本地采集器读取文件列表元数据。
2. 在不下载 PDF 的情况下，为用户选定的百度网盘目录生成可恢复、可核验的本地目录快照。
3. 在 Obsidian 的 Cloud Catalog 视图中按文件名、疑似 ISBN 和云端文件夹路径搜索 PDF。
4. 查看结果的云端路径、文件大小和服务端修改时间。
5. 通过显式按钮复制文件名或云端路径，并打开百度网盘入口继续人工定位。
6. 在权限、限流或网络故障时看到“未完成”状态，而不是得到错误的完整性结论。

## 3. 非目标

首期不会：

- 下载、缓存、预览或解析 PDF 正文；
- 对 PDF 执行 OCR、摘要、嵌入或 AI 问答；
- 为每个 PDF 批量生成 Markdown 笔记；
- 把目录快照写入真实 Vault、插件 `data.json`、Git 仓库或同步目录；
- 上传、移动、复制、重命名、删除或分享百度网盘文件；
- 使用百度账号密码、浏览器 Cookie、隐藏接口或非官方登录工具；
- 承诺在未经真实小目录验证前能够遍历整个网盘根目录；
- 运行既有 A/B benchmark、long-pilot、public-v1、压力脚本或对照模型实验。

用户以后可以单独批准“从选中目录项创建一张参考笔记”，但该写入能力不属于本规格。

## 4. 核心原则

### 4.1 三层分离

```text
百度网盘原始 PDF
        ↓ 只读取目录元数据
Vault 外本地目录快照
        ↓ 只读加载派生索引
Obsidian Cloud Catalog 视图
```

- 百度网盘继续保存原始 PDF。
- 本机仅保存体积较小的目录元数据和搜索索引。
- Obsidian 负责检索和定位，不承担 3.2 TB 文件存储。

### 4.2 默认只读

只读不是界面提示，而是代码边界：目录采集网络端口只能构造官方 OAuth 请求和 `GET /rest/2.0/xpan/file?method=list` 请求。实现中不存在通用百度网盘请求执行器，也不提供下载或文件管理方法。

### 4.3 完整性不冒进

只有选定根目录的全部分页和全部子目录都成功完成时，扫描结果才能成为活动快照。部分扫描、权限拒绝和不可恢复错误必须保留为未完成扫描，不能覆盖上一次完整快照。

### 4.4 私有元数据最小化

云端文件名和路径属于私有元数据。它们只保存在用户本机的受限应用数据目录中；测试报告、日志、PMH checkpoint 和错误遥测不得包含文件名、路径、Token 或书目内容。

## 5. 架构

首期由五个相互隔离的单元组成。

### 5.0 配置与扫描启动边界

真实授权前，用户必须在百度网盘开放平台拥有可用的自有应用，并在设置页显式录入该应用的 AppKey 和 SecretKey。首期固定使用官方 `redirect_uri=oob`：设置页打开百度官方授权页，用户只把官方页面显示的一次性授权码粘贴回本地插件，不启动本机 HTTP 监听器，也不登记 localhost、局域网地址或第三方回调域名。凭证只有在目标 Obsidian 版本的 SecretStorage 后端通过隔离验证后才能保存；项目文件和插件配置中只保留“已配置”状态。官方授权页只提供 `basic,netdisk` 网盘读写范围，不提供目录选择器；用户已在看到该范围后明确接受。该外部授权范围大于产品需求，因此代码能力必须继续收窄为 OAuth、Token 交换和 `GET + method=list`，不得因为授权范围较宽而增加任何写入接口。若个人应用创建、OOB 授权或文件列表权限无法通过官方流程获得，真实授权在此处停止，不能改用 Cookie、账号密码或第三方登录工具绕过。

授权成功本身不得触发目录枚举。首期以用户手动输入或粘贴的规范化云端绝对路径作为扫描根目录；应用可以在用户点击后只列举该明确路径的直接子项，供用户核对路径，但不能为了生成选择器自动遍历 `/` 或其他父目录。

开始前必须显示一次只读扫描确认，至少包括：所选根目录、是否递归包含子目录、只保留 PDF 元数据、不会下载正文，以及当前活动快照不会在未完整成功时被替换。只有用户点击“开始只读扫描”后才能创建 scan ID 并发出列表请求。首期网络列举并发固定为 1。

### 5.1 `BaiduOAuthPort`

职责：

- 在系统浏览器中打开百度官方授权页；
- 固定发送 `redirect_uri=oob`，不构造其他回调地址；
- 在设置页接受用户主动粘贴的一次性授权码；
- 只允许一个十分钟有效的本地授权尝试，并确保授权码最多提交一次；
- 交换和刷新 Access Token；
- 将 AppKey、SecretKey、Access Token 和 Refresh Token 交给凭证端口保存。

边界：

- 不接收或保存百度账号密码；
- 凭证不得通过命令行参数、环境变量、URL 日志或项目文件传递；
- 一次性授权码只允许包含 1 至 512 个可见 ASCII 字符，不得包含空白或控制字符，提交后立即从输入框和内存暂存中清除；
- OAuth 取消、授权尝试过期或授权码交换失败时不保存授权码、不创建目录快照；
- 官方文档没有保证 OOB 页面会返回可由插件验证的 `state`，因此首期不宣称具备回调式 `state` 校验；安全边界改为用户主动粘贴、单一活动尝试、十分钟超时和授权码单次提交；
- 首期不假设百度支持 PKCE，也不启动本机 HTTP 服务。

### 5.2 `CatalogCredentialPort`

职责：

- 通过 Obsidian SecretStorage 保存应用凭证和 OAuth Token，并在真实使用前验证其目标平台后端；
- 按服务名和百度账号授权身份隔离条目；
- 提供读取、替换和撤销操作；
- 卸载或用户撤销授权时提供明确清理入口。

边界：

- 插件 `data.json` 只允许保存非敏感状态，例如“是否已配置”；
- 日志和错误对象只出现固定错误码，不出现凭证值；
- 测试使用内存假实现，不访问真实 SecretStorage 后端。

### 5.3 `BaiduCatalogSourcePort`

职责：

- 对用户明确选择的根目录分页列举直接子项；
- 返回最小文件元数据；
- 将 Token 过期、权限拒绝、频率限制和网络错误转换成稳定错误类型。

允许的远端操作只有：

- OAuth 授权与 Token 交换；
- `GET https://pan.baidu.com/rest/2.0/xpan/file`；
- 查询参数 `method=list`。

任何其他主机、路径、HTTP 方法或 `method` 值都必须在发出网络请求前被拒绝。首期不调用 `listall`、官方 MCP 写工具或下载接口。

### 5.4 `CatalogScanService`

职责：

- 以广度优先方式遍历用户选定目录；
- 处理分页、限流、Token 刷新和可取消执行；
- 定期持久化待扫描目录队列、分页位置和已完成计数；
- 对 `fs_id` 和规范化云端路径去重；
- 仅保留目录项和扩展名为 `.pdf` 的文件记录；
- 为其他扩展名只累计数量，不保存名称；
- 成功完成后原子提升新快照。

扫描必须串行或使用极低并发。遇到官方频率限制时按错误类型延后并保存 checkpoint，不进行紧密重试。

### 5.5 `CatalogSnapshotPort`

快照位于 Vault、Git 仓库和 Obsidian 插件目录之外：

```text
~/Library/Application Support/Knowledge Workbench/baidu-catalog/
  active.json
  snapshots/<snapshot-id>/catalog.ndjson
  scans/<scan-id>/checkpoint.json
  scans/<scan-id>/receipt.json
```

文件权限应限制为当前 macOS 用户可读写。`active.json` 只保存活动快照 ID、结构版本、完成时间、记录数和内容哈希。

`catalog.ndjson` 中每条记录使用以下逻辑结构：

```json
{
  "schemaVersion": 1,
  "source": "baidu-netdisk",
  "fsId": "30995775581277",
  "kind": "file",
  "path": "/资料/示例书.pdf",
  "parentPath": "/资料",
  "filename": "示例书.pdf",
  "extension": "pdf",
  "sizeBytes": 1048576,
  "serverModifiedAt": 1596078161
}
```

`fsId` 必须保存为十进制字符串，避免 JavaScript 安全整数范围导致精度丢失。字符串统一执行 Unicode NFC 规范化，但原始文件名内容不做改写。

扫描 receipt 只允许保存：扫描状态、开始和完成时间、目录数、PDF 数、忽略文件数、错误码计数、重试次数、快照哈希和结构版本。receipt 不保存实际文件名、路径或凭证。

## 6. Obsidian 集成

### 6.1 独立领域模型

云端目录项不复用现有 `DocumentRecord`。`DocumentRecord` 表示 Vault 中的 Markdown 文件，并参与 Today、分类、地图、建议和 AI 流程；云端 PDF 目录只是可定位的外部资产。

新增独立模型：

```ts
interface CloudCatalogRecord {
  readonly fsId: string;
  readonly path: string;
  readonly parentPath: string;
  readonly filename: string;
  readonly title: string;
  readonly isbnCandidates: readonly string[];
  readonly sizeBytes: number;
  readonly serverModifiedAt: number;
}
```

`title` 只由文件名去除最后一个 `.pdf` 后得到。ISBN 仅作为从文件名提取的候选搜索键，不作为已核实书目事实。

### 6.2 `CatalogSearchService`

职责：

- 从活动 NDJSON 快照建立只读内存索引；
- 支持文件名、标题、ISBN 候选和路径片段搜索；
- 对中文标题使用与现有索引一致的 Unicode 规范化和双字搜索思路；
- 提供文件夹前缀和修改时间筛选；
- 在快照变更时原子替换搜索索引。

该服务不读取 Vault，不修改现有 Knowledge Map，不调用 AI，也不产生组织建议。

### 6.3 Cloud Catalog 视图

Workbench 新增 `Cloud Catalog` 标签页，包含：

- 当前快照状态、完成时间和 PDF 总数；
- 搜索框；
- 文件夹筛选；
- 分页或虚拟化结果列表；
- 每条结果的标题、父目录、大小和修改时间；
- `Copy filename`、`Copy cloud path` 和 `Open Baidu Netdisk` 三个显式按钮。

复制动作只在用户点击后执行。`Open Baidu Netdisk` 打开官方入口，不构造未经官方文档保证的文件深链，也不自动粘贴搜索词。

若没有完整快照，视图显示设置引导或上一次完整快照；未完成扫描不得伪装成最新完整目录。

## 7. 数据流

### 7.1 首次授权与小目录验证

1. 用户在设置页选择“连接百度网盘”。
2. 系统浏览器打开固定使用 `redirect_uri=oob` 的百度官方 OAuth 页面。
3. 用户在官方页面登录并授权，将页面显示的一次性授权码粘贴回本地设置页。
4. 插件在一个活动授权尝试内交换授权码，立即清除输入值，并将长期凭证交给已验证的 SecretStorage 后端。
5. 用户手动输入并再次确认一个不敏感小目录的绝对云端路径；授权成功本身不触发根目录或父目录枚举。
6. 设置页显示扫描根目录和递归范围，用户点击“开始只读扫描”。
7. 采集器只列举该目录并生成未激活的候选快照。
8. 系统只报告计数、状态和错误码；用户核对客户端可见数量。
9. 用户显式确认验证通过后，候选快照成为活动快照。

此流程不安装插件到真实 Vault。真实百度小目录验证和真实 Vault 只读验收是两个独立授权边界。

### 7.2 后续刷新

1. 用户手动发起刷新；首期不后台定时扫描。
2. 采集器从新的 scan ID 开始，可在中断后恢复。
3. 旧活动快照在整个扫描期间继续可用。
4. 新扫描完整成功后，先校验 NDJSON、记录数和哈希，再原子更新 `active.json`。
5. Obsidian 观察到活动快照变化后重建搜索索引。

## 8. 错误处理

| 情况 | 行为 |
| --- | --- |
| 用户取消 OAuth 或关闭授权码输入 | 返回 `authorization-canceled`，不写凭证和快照 |
| 没有活动授权尝试或授权码已被提交 | 返回 `authorization-attempt-unavailable`，立即清除输入并停止 |
| 活动授权尝试超过十分钟 | 返回 `authorization-attempt-expired`，立即清除输入并停止 |
| 授权码为空、超长、包含空白或控制字符 | 返回 `authorization-code-invalid`，立即清除输入并停止 |
| 授权码交换失败或响应无效 | 返回 `authorization-exchange-failed`，不保留授权码并要求重新开始授权 |
| 未配置官方应用凭证或 OOB 授权不可用 | 停在设置页，不启动 OAuth，不改用其他登录方式 |
| 扫描路径为空或不是规范化绝对路径 | 返回 `invalid-scan-root`，不发出列表请求 |
| Token 过期 | 单次刷新后重试原列表请求；刷新失败则要求重新授权 |
| 目录无权访问 | 标记扫描 `partial`，保留 checkpoint，不提升快照 |
| 命中频率限制 | 保存 checkpoint，按服务端信息或有上限退避后继续 |
| 网络中断 | 保存 checkpoint，允许用户稍后恢复 |
| NDJSON 记录无效 | 拒绝整个候选快照，继续使用旧活动快照 |
| 内容哈希不匹配 | 标记快照损坏，不加载、不自动修复 |
| Vault 不可用 | Cloud Catalog 仍不尝试写 Vault；插件显示本地目录不可用状态 |

错误消息不得回显请求 URL，因为官方列表 API 的 URL 参数中包含 Access Token。

## 9. 安全与隐私验收

实现必须证明：

1. 网络端口没有下载、上传、文件管理和分享方法。
2. 非 `GET + method=list` 的百度文件请求在本地被拒绝。
3. Token、SecretKey、文件名和路径不会进入日志、异常消息、测试快照、Git diff 或 PMH checkpoint。
4. Catalog 扫描路径不调用 `VaultWritePort`。
5. Cloud Catalog 视图不把目录项发送给 AI endpoint。
6. 真实网盘验证只在用户再次确认的小目录中执行。
7. 真实 Vault 在获得新的明确授权前保持未安装、未打开、未扫描和未写入。
8. OAuth 成功不会自动列举目录；没有显式扫描确认时，假网络端口收到的列表请求数必须为零。
9. OOB 授权码不会进入日志、异常、插件数据、目录快照、测试快照或 PMH checkpoint，并在提交、取消或超时后清除。
10. 尽管百度 OAuth 页面授予网盘读写范围，生产依赖图仍不存在上传、移动、复制、重命名、删除或分享能力。

## 10. 测试策略

### 10.1 单元测试

- OOB 授权尝试的单实例、十分钟超时、授权码单次提交、输入清除和固定错误码；
- 扫描根目录规范化、非法路径拒绝和显式启动门；
- SecretStorage 端口的保存、替换、撤销、后端隔离验证和错误映射；
- 网络请求白名单；
- 百度文件列表响应解码；
- `fs_id` 字符串精度；
- Unicode NFC、扩展名和 ISBN 候选提取；
- 分页、目录队列、去重、取消和恢复；
- receipt 字段白名单；
- NDJSON 校验和活动快照原子提升；
- 搜索、筛选、稳定排序和不可变返回值。

### 10.2 集成测试

- 使用本地假百度 API 完成多目录、多分页扫描；
- Token 过期后只刷新一次并恢复扫描；
- 权限拒绝、频率限制和中断不会覆盖旧快照；
- Cloud Catalog 能读取新快照并搜索，但不触发 Vault 或 AI 端口；
- 所有日志经过敏感字段扫描。

### 10.3 性能验收

使用正常产品测试夹具，而不是 PMH 压力脚本：

- 100,000 条合成 PDF 目录记录在目标 Mac 上 10 秒内完成加载和搜索索引构建；
- 50 个固定查询的本地搜索 p95 不超过 250 毫秒；
- 结果列表始终只渲染可见窗口附近的有限条目。

性能测试不得调用百度网盘、真实 Vault 或 PMH。

### 10.4 真实小目录验收

在用户明确选择的非敏感目录中：

- 验证列表请求成功且下载字节数为零；
- 将返回项目总数与百度网盘客户端可见数量人工核对；
- 证据只记录计数、状态、耗时和错误码；
- 完成后停止，不自动扩大到根目录。

## 11. 首期验收标准

首期只有在以下条件全部满足时完成：

- 用户可以通过官方 OOB 授权码流程完成授权，长期凭证只存在经过验证的 SecretStorage 后端；
- 用户在看到全盘网盘读写范围后明确同意，设置页同时说明本产品只调用只读目录列表接口；
- 没有可用的用户自有百度开放平台应用时，产品明确停止并说明官方前置条件；
- OAuth 成功后，在用户确认扫描根目录前不会发出文件列表请求；
- 小目录验证证明只读取元数据且没有 PDF 下载；
- 完整快照与部分扫描状态被明确区分；
- Obsidian 可以搜索至少 100,000 条合成目录记录；
- 搜索结果可以显式复制文件名或云端路径；
- Cloud Catalog 不改变现有 Today、Knowledge Map、Suggestions、History 和 AI 行为；
- 自动化测试、类型检查、构建和安全日志扫描通过；
- 未获得单独授权前，真实 Vault 保持不变；
- 未运行旧实验、压力脚本或对照模型实验。

## 12. 工程验证 checkpoint 规则

本任务同时作为 PMH 长期真实工程验证样本，但产品开发优先：

- 不为实验拉长上下文、制造错误或重复开发；
- 不读取另一个实验任务的对话、提交、日志或记忆；
- 每完成 3 至 5 个可验证阶段建立 checkpoint 并停止汇报；
- checkpoint 只记录 Git 提交、实际功能、真实测试结果、错误方向与返工次数、可获得的 Token 统计、PMH recall 数量和 Token 量，以及是否发现跨项目或跨模型污染；
- checkpoint 不输出 recall 内容、云端文件名、路径、书目内容或任何凭证；
- 到达 checkpoint 后不自行启动对照模型实验。

## 13. 已知风险与停止条件

- 百度普通文件列表是否允许新建个人应用访问用户手工指定的现有小目录，仍需只读实测；权限拒绝时停止，不尝试父目录或根目录扩权。
- OAuth 同意范围包含网盘写入能力，权限大于首期产品所需；安全性依赖严格的生产依赖图、请求白名单和用户可见撤销入口，任何写操作进入依赖图都必须阻断发布。
- 实际频率配额可能使首次全量扫描耗时较长；扫描必须可恢复，不能以提高并发规避平台限制。
- 桌面应用无法从技术上隐藏嵌入代码的固定 SecretKey，因此 SecretKey 不得编译进产物，必须由用户自己的应用凭证通过已验证的 SecretStorage 后端提供。
- 个人使用软件应用与 OOB 页面已通过真实验证；该应用能否列出用户手工指定的既有小目录仍待 Task 13 的单次只读验收。
- 云端目录路径可能暴露个人信息；所有证据和报告继续使用计数与固定状态码。
- 若目录规模超过本地内存索引能力，后续单独设计磁盘索引；首期不提前引入 SQLite 或第三方搜索引擎。
