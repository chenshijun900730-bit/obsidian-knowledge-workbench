# Knowledge Workbench 百度网盘文件夹浏览器设计

- 状态：界面、架构与验收设计已获用户确认；书面规格待用户复核
- 日期：2026-08-31
- 适用产品：Knowledge Workbench for Obsidian
- 前置规格：`2026-08-23-smart-cloud-directory-picker-design.md`
- 变更性质：为现有智能目录选择器增加按层浏览和父目录／分类目录选择语义

## 1. 背景与结论

现有智能云端目录选择器已经能够合并最近目录、TXT 名称提示、会话缓存和显式同名定位，但首次使用和更换目录时仍依赖完整路径、已有候选或全盘同名定位。用户实际需要的是百度网盘客户端式的文件夹选择体验：从最近目录开始，必要时显式进入网盘根目录，再通过面包屑逐层进入和选择文件夹。

本阶段采用已确认的“单层按需浏览”方案：

1. 打开选择器只显示最近目录和会话缓存，不访问百度；
2. 用户显式点击“从网盘根目录浏览”后，本次 Obsidian 会话首次确认一次；
3. 每次只读取当前路径的直接子项，不递归预取；
4. 每轮最多检查 20,000 条目录项，底层按最多 20 个、每个 1,000 条的百度列表请求执行；
5. 百度返回的文件条目通过既有响应校验后立即丢弃，只把文件夹放入会话缓存和界面；
6. 用户既可选择当前父目录，也可在父层直接选择一个已识别的分类目录；
7. 选择分类目录时不进入该目录，不为“选择”而列出其中的大量 PDF；
8. 选择目录只形成核验草稿，仍需通过现有外层确认后才可开始核验。

本设计不下载 PDF、不索引正文、不写入笔记、不修改百度网盘内容，也不允许把 `/` 作为扫描或核验根目录。

## 2. 与前置规格的关系

本规格增量扩展前置“智能云端目录选择器”规格：

- 保留最近 10 条准确路径、TXT 名称提示、会话缓存、手工输入和清空最近目录；
- 保留“在网盘中定位同名目录”作为高级恢复入口，其既有 BFS 预算和确认语义不变；
- 将“最近目录 + 逐层浏览”提升为日常主要入口；
- 新的逐层浏览服务不得复用或隐式启动同名定位器的 BFS；
- 本规格中的每层读取、20,000 条轮次预算和根目录会话确认只约束新浏览模式；
- 扫描、分类核验、OAuth、SecretStorage、checkpoint、acceptance 构建和真实 Vault 写入边界保持不变。

如果两份规格的交互描述冲突，以本规格的逐层文件夹浏览交互为准；其余安全和数据语义继续以前置规格为准。

## 3. 用户目标与成功标准

完成后，用户应当能够：

1. 在不手工输入完整云端路径的情况下打开文件夹选择器；
2. 先从最近使用的目录开始，必要时显式从百度网盘根目录逐层浏览；
3. 通过面包屑返回任意已进入的上级；
4. 区分同名文件夹的完整路径；
5. 选择当前父目录，继续使用核验页已勾选的一个或多个分类；
6. 在父层直接选择一个已识别的分类目录，由系统显示实际核验父目录；
7. 查看本轮已检查条目、已发现文件夹、列表请求数、游标和当前层完整性；
8. 在达到上限、网络失败、取消或令牌失效后，从准确游标继续或重新连接；
9. 使用键盘完成进入、返回、选中、确认和取消；
10. 明确知道选择目录不会下载 PDF、写入笔记或自动开始核验。

验收级成功标准：

- 打开 Modal、本地搜索、切换最近目录和读取已有会话缓存的百度请求数为 `0`；
- 未通过本次会话首次根目录确认前，浏览服务请求数为 `0`；
- 一轮浏览最多开始 20 次列表请求，最多检查 20,000 条响应项；
- 底层每次列表请求继续使用固定 `limit=1000`，不得把 `20_000` 直接传给百度接口；
- 浏览只请求当前一层，不把发现的子目录自动加入遍历队列；
- 文件和 PDF 不进入结果、DOM、最近目录或持久化缓存；
- 选择已识别分类目录不会对该分类路径调用 `listDirectory`；
- `/` 永远不能成为选择结果、最近目录、扫描根或核验根；
- 选择结果只更新草稿和分类选择，不调用扫描、核验或恢复服务；
- acceptance 构建继续没有 OAuth、SecretStorage、百度列表、根浏览或同名定位能力。

## 4. 非目标

本阶段不会：

- 递归预加载或缓存整棵百度网盘目录树；
- 在插件启动时、Modal 打开时或搜索输入变化时访问百度；
- 实现系统原生 macOS 文件夹选择框；
- 下载、打开、解析、OCR、摘要、嵌入或索引 PDF 正文；
- 显示百度列表中的普通文件或 PDF；
- 上传、移动、重命名、删除或修改云端文件；
- 将根目录授权、云端 `fsId`、分页游标或完整树持久化；
- 猜测同名分类、自动选定身份冲突目录或静默修复路径；
- 把一轮 20,000 条预算描述为整个网盘的完成百分比；
- 一次性向 DOM 插入 20,000 行；
- 自动循环重试网络错误、限流或达到预算的运行；
- 放宽现有扫描和核验对 `/` 的拒绝；
- 改变现有核验 checkpoint、覆盖层、活动 manifest 或统一目录记录语义；
- 在未另行取得明确授权时执行真实百度验收、安装新构建或修改真实 Vault。

## 5. 交互设计

### 5.1 打开状态

选择器打开时默认显示：

- “最近使用”视图；
- 本地模糊搜索框；
- 最多 10 条最近准确路径；
- 本次插件会话已经完整校验并缓存的目录；
- 单独的“从网盘根目录浏览”动作；
- 已有高级“在网盘中定位同名目录”恢复入口。

打开状态不得读取 SecretStorage、刷新 OAuth 或调用百度列表端口。若当前已有合法非根路径，选择器可以把它显示为初始选择，但不能后台验证其是否仍存在。

### 5.2 根目录首次确认

每个 Obsidian 插件进程中，第一次点击“从网盘根目录浏览”时显示确认框：

- 将只读列出根目录当前一层的元数据；
- 不递归扫描；
- 不显示或下载 PDF；
- 本轮最多检查 20,000 条目录项和开始 20 次列表请求；
- `/` 只作为浏览入口，不能成为最终选择；
- 关闭或重新加载插件后需要重新确认。

取消确认不改变当前结果、搜索词或选择。确认值只保存在内存，不写普通设置、SecretStorage、历史或操作回执。进入非根最近目录不需要根目录确认，但仍由用户明确点击该目录后才可发出列表请求。

### 5.3 当前层浏览

浏览视图包含：

- 面包屑；
- 当前路径名称和完整路径；
- 当前层文件夹列表；
- “选择当前文件夹”；
- 当前层读取状态；
- 当前层未完整时的“继续加载本层”；
- 可展开的“运行详情”；
- 取消和返回最近目录。

文件夹行采用两个清晰动作：

1. 文件夹名称或尾部箭头进入该文件夹；
2. 行选择控件只高亮该文件夹，底部主要动作变为“选择此文件夹”。

这避免把“进入”和“选择”混成一次不可逆点击。面包屑只能导航到本次会话已经进入的祖先路径，不触发递归查询。

### 5.4 单层不完整状态

每轮从当前游标连续读取，直到发生以下任一条件：

- 百度返回少于 1,000 条，当前层完整；
- 已检查 20,000 条；
- 已开始 20 次列表请求；
- 达到 120,000 毫秒轮次时限；
- 用户取消；
- 网络、授权、限流或响应校验失败。

未读取完整时，界面必须显示：

- “当前层尚未完全加载”；
- 已检查条目数；
- 已找到文件夹数；
- 停止原因；
- “继续加载本层”或与错误相匹配的下一步。

“继续加载本层”开始一个新的 20,000 条轮次，从上一完整页的 `nextStart` 继续。它不重复前一轮，不进入子目录，也不自动启动。

### 5.5 搜索

搜索只覆盖：

- 最近准确路径；
- 本次会话已经加载的文件夹；
- 前置规格保留的 TXT 名称提示；
- 前置规格保留的同名定位结果。

搜索不触发云端请求。结果必须显示名称、规范化完整路径、来源和状态。同名不同路径分别显示；相同路径不同 `fsId` 显示冲突并禁用。

### 5.6 选择父目录

选择当前目录或普通子文件夹作为父目录时：

- `selectedPath` 和 `verificationRoot` 相同；
- 核验页当前勾选的合法分类保持不变；
- 选择器关闭后，核验页显示新的实际核验父目录；
- 不调用扫描、核验、恢复或目录内部列表。

根目录 `/` 不显示“选择当前文件夹”，也不能通过键盘、DOM 修改或手工返回值绕过。

### 5.7 选择分类目录

仅在核验用途且当前子文件夹能唯一匹配活动 TXT 目录中的一个非 `txt-root-items` 一级分类时，行显示“分类”状态并允许分类选择。

唯一匹配规则：

- 以当前父路径和候选 group 的规范化 `rootRelativePath` 构造期望云端路径；
- 期望路径必须正好等于当前层返回的直接子目录路径；
- 匹配结果必须恰好一个；
- 目录路径和 `fsId` 必须通过本次会话身份校验。

选择分类目录后返回：

- 用户选择目录：该分类的完整云端路径；
- 实际核验父目录：当前层路径；
- 本次核验分类：匹配的唯一 `groupKey`；
- 选择方式：`category`。

核验页把分类选择收窄为该唯一分类，并在外层确认摘要中同时显示“选择目录”“实际核验父目录”和“本次核验分类”。选择器不得进入或列出分类目录内部内容。

零匹配或多匹配时不得猜测分类。该文件夹仍可作为普通目录进入或选择，但不能使用“分类目录自动换算父目录”语义。

### 5.8 外层确认

选择器返回后，现有扫描或核验确认门保持独立：

- 目录选择不等于开始核验；
- 核验页重新计算实际根、分类数、候选 PDF 数和固定运行预算；
- 用户点击“确认并开始只读核验”后，仍显示最终确认框；
- 已暂停批次、根目录锁定和 source import 不匹配规则不因本功能放宽。

## 6. 数据模型与接口

### 6.1 结构化选择结果

现有 `Promise<string | null>` 无法表达“用户选择分类目录，但实际核验父目录不同”。选择器改为结构化返回：

```ts
type CloudDirectorySelection =
  | Readonly<{
      kind: "directory";
      selectedPath: string;
      effectiveRoot: string;
    }>
  | Readonly<{
      kind: "category";
      selectedPath: string;
      effectiveRoot: string;
      groupKey: string;
    }>;

interface CloudDirectoryPickerPresenter {
  request(input: CloudDirectoryPickerRequest): Promise<CloudDirectorySelection | null>;
}
```

`selectedPath` 用于向用户解释其选择；`effectiveRoot` 才能写入扫描／核验路径草稿。两者都必须是规范化非根绝对云端路径。`cloudFsId` 不出现在持久化选择结果中。

### 6.2 用途上下文

调用方显式声明用途：

```ts
type CloudDirectoryPickerPurpose =
  | Readonly<{ kind: "scan" }>
  | Readonly<{
      kind: "verification";
      groups: readonly Readonly<{
        groupKey: string;
        rootRelativePath: string;
        label: string;
      }>[];
    }>;
```

扫描用途只返回 `kind: "directory"`。只有核验用途且满足唯一 group 匹配时才可返回 `kind: "category"`。

### 6.3 单层浏览运行时

新增独立只读运行时，不复用 BFS 定位器：

```ts
interface CloudDirectoryBrowserRuntime {
  loadLayer(
    input: Readonly<{ path: string; start: number }>,
    signal?: AbortSignal,
  ): Promise<CloudDirectoryBrowseRound>;
  snapshot(path: string): CloudDirectoryLayerSnapshot | null;
  clear(): void;
  dispose(): void;
}

interface CloudDirectoryBrowseRound {
  readonly path: string;
  readonly status: "complete" | "paused" | "canceled";
  readonly stopReason:
    | "complete"
    | "entry-limit"
    | "list-request-limit"
    | "time-limit"
    | "user-canceled";
  readonly nextStart: number | null;
  readonly checkedEntryCount: number;
  readonly directoryCount: number;
  readonly listRequestCount: number;
  readonly elapsedMs: number;
}
```

网络、授权、限流和响应错误继续使用现有有限 `CatalogError` 代码，不把原始异常文本放入摘要或 UI。

### 6.4 固定轮次预算

```ts
const CLOUD_DIRECTORY_BROWSE_ROUND_BUDGET = Object.freeze({
  maxEntryCount: 20_000,
  maxListRequestCount: 20,
  maxDurationMs: 120_000,
} as const);
```

“20,000”是一次用户触发轮次检查的响应项上限，不是百度接口单页参数，也不是 DOM 同时显示行数。源适配器继续要求 `limit: 1000`。

## 7. 分页、原子性与身份校验

### 7.1 请求计数

- 在真正发送请求之前立即把列表请求数加一；
- 失败请求也计入本轮 20 次上限；
- 未发送的计划请求不计数；
- 摘要同时显示本轮请求数和当前层会话累计请求数；
- 继续加载新一轮时，本轮计数归零，当前层累计计数继续增加。

### 7.2 页原子提交

每个 1,000 条页按以下顺序处理：

1. 检查 signal、generation、请求数和时间预算；
2. 发出一个列表请求并计数；
3. 解码完整响应；
4. 验证条目数量不超过 1,000；
5. 验证每条路径、文件名、直接父路径、`fsId` 和目录标记；
6. 检查当前页、当前层缓存与会话缓存的路径／身份双向唯一；
7. 重新检查 signal、generation 和时间预算；
8. 只把目录条目作为一个原子页提交；
9. 文件条目、PDF 和其他普通文件立即丢弃；
10. 提交后才把 `nextStart` 增加 1,000。

任一步失败时，本页不产生半缓存，`nextStart` 保持在上一完整页。随后重试会重新读取本页。

### 7.3 完整性

- 响应条目少于 1,000 时，当前层标记 `complete` 且 `nextStart=null`；
- 正好 1,000 条时，只能说明可能还有下一页，不能标记完整；
- 达到 20,000 条、20 次请求或 120 秒时标记 `paused`；
- 已暂停层的已提交目录可以选择，但 UI 必须持续显示“当前层尚未完全加载”；
- 浏览器不得因为已找到一个同名目录而暗示当前层完整。

### 7.4 根路径隔离

浏览服务使用专用内部路径策略允许 `/` 作为只读列表入口，但不得修改 `normalizeCatalogScanRoot` 的非根约束。结构化选择结果、最近目录写入和外层扫描／核验入口都必须再次拒绝 `/`。

## 8. 状态、缓存与生命周期

### 8.1 会话缓存

每个规范化路径的会话缓存包含：

- 已原子提交的文件夹；
- 每个文件夹的 `path`、`filename` 和会话 `fsId`；
- `nextStart`；
- 当前层是否完整；
- 已检查条目和累计列表请求数；
- 最近停止原因。

它不包含普通文件、PDF、响应正文、Token、凭据、授权码或原始错误。

### 8.2 持久化

继续只持久化前置规格允许的最近 10 条完整路径。不得持久化：

- 根目录浏览确认；
- 当前层缓存；
- 分页游标；
- 云端 `fsId`；
- 已发现的整棵目录树；
- 运行中的请求、AbortController 或 generation；
- PDF 和普通文件条目。

### 8.3 清理

关闭 Modal 只取消当前请求并清理敏感 DOM，但本次插件会话的已提交文件夹缓存可以继续供再次打开使用。以下事件清空浏览缓存和根目录确认：

- 插件卸载或 reload；
- Obsidian 进程结束；
- 显式移除本地凭据；
- composition dispose；
- 身份冲突导致会话缓存不再可信。

### 8.4 并发与迟到响应

- 每次进入目录、继续加载或重试都生成新的 operation generation；
- 离开当前层、关闭 Modal、按 Escape、断开连接或 dispose 会 abort 当前 operation；
- 所有缓存提交、状态更新和 DOM 更新前核对 generation 与 signal；
- 迟到响应不得覆盖新路径、复活 Modal、改变选择、写最近目录或启动后续请求；
- 重复点击同一运行按钮不得并发启动第二轮；
- Promise 只 settle 一次，焦点恢复到打开选择器的控件。

## 9. 进度与性能

### 9.1 进度含义

主界面显示：

- 已检查 `N / 20,000` 条；
- 已发现文件夹数；
- 当前层“读取中／完整／尚未完整／已取消／错误”；
- 取消动作。

进度条只表示本轮 20,000 条检查预算的使用量。若百度提前返回不足一页，状态直接变为“当前层已完整”，而不是强制填满进度条。

“运行详情”显示：

- 本轮列表请求 `N / 20`；
- 当前层累计请求；
- 下一页游标；
- 已用时间 `N / 120 秒`；
- 当前层是否完整；
- 停止原因。

### 9.2 渲染压力

网络轮次可以检查 20,000 条，但文件夹结果必须使用现有窗口化列表模式或等价的有界 DOM 实现：

- 只渲染可视区域和有限 overscan；
- 同时存在的结果行保持固定上限，不随 20,000 线性增加；
- 滚动后仍能访问最后一条，不能通过截断列表丢结果；
- 搜索和排序使用内存数据，不复制完整响应对象；
- 切换目录时及时释放旧 DOM、事件监听和临时排序数组；
- 继续保留长路径换行和窄窗口可达性。

不得为了实现 20,000 上限一次性创建 20,000 个 DOM 节点。

## 10. 错误与恢复

### 10.1 用户取消

- 立即 abort 当前请求或阻止下一请求开始；
- 保留取消前已经完整提交的页面；
- 当前未提交页丢弃；
- 显示“已取消”和准确 `nextStart`；
- 不自动继续。

### 10.2 网络错误与限流

- 不自动循环重试；
- 保留完整页和上一游标；
- 使用固定安全错误文案和“重试当前页”；
- 重试仍计入新的轮次预算；
- 不显示响应正文、原始错误、Token、凭据或堆栈。

### 10.3 令牌过期

沿用现有 source adapter 的一次令牌刷新语义。刷新成功后只重试当前请求；刷新失败则停止本轮并提示重新连接。不得形成无限刷新或重试循环。

### 10.4 无子文件夹

当前层完整但没有子文件夹时显示“当前文件夹没有子文件夹”。合法非根当前路径仍可通过“选择当前文件夹”返回；根路径不可选。

### 10.5 响应异常与身份冲突

- 无效响应拒绝整个页面；
- 同一路径不同 `fsId` 或同一 `fsId` 不同路径视为会话身份冲突；
- 冲突项不可选择、进入或写最近目录；
- 若冲突使当前层缓存整体不可信，清除此层并要求重新连接或重新打开选择器；
- 不任意选择一个身份继续。

### 10.6 陈旧最近目录

最近目录继续只表示“以前使用”，不声称仍然存在。用户点击后若列表返回不存在或无权限，显示固定错误并允许返回最近目录；不在后台删除该项。用户可通过既有“清空最近目录”主动移除。

## 11. 组件边界

定向新增或调整：

- `catalog/cloud-directory-browser.ts`：固定轮次预算、单层分页、页原子缓存和摘要；
- `catalog/cloud-directory-page-validator.ts`：复用并补充直接父路径与身份校验，不降低既有约束；
- `ui/cloud-directory-picker.ts`：最近／浏览视图、面包屑、根确认、行进入与选择、进度和结构化结果；
- `ui/cloud-directory-field.ts`：接收结构化选择并显示用户选择与实际生效根；
- `ui/verification-page.ts`：传入 group 上下文、处理 category 结果、收窄 group 选择并显示外层摘要；
- `ui/settings-sections.ts`：扫描用途只采用 directory 结果，设置页共享相同浏览器；
- `ui/workbench-controller.ts`：在 controller 层回填 `effectiveRoot` 和 category `groupKey`，不实现分页或 DOM；
- `runtime/runtime-composition.ts` 与 normal composition：注入一个共享 Baidu source 的 browser factory；
- `i18n/workbench-directory-picker-i18n.ts` 及中英文词典：新增浏览、完整性、进度、停止、分类选择和安全文案；
- `styles.css`：面包屑、窗口化列表、选中态、进度和窄窗口布局。

分层规则：

- Modal 不直接读取 SecretStorage、普通设置或发送 HTTP；
- Browser service 不依赖 DOM、Obsidian Modal、TXT store 或核验 runtime；
- Controller 不实现分页、响应校验或模糊评分；
- 生产层复用现有 `BaiduCatalogSourcePort`、OAuth 刷新和请求适配器，不创建第二套凭据或网络实现；
- offline、disabled 和 acceptance composition 不注入 browser runtime。

## 12. 键盘与无障碍

- 打开时焦点进入搜索框；
- Tab 可达视图切换、根浏览、面包屑、文件夹行、继续加载、取消和选择；
- 上／下方向键移动高亮文件夹；
- Enter 默认进入高亮文件夹；
- 明确的选择快捷键或按钮选择高亮项，避免 Enter 同时承担进入和确认；
- Backspace 仅在搜索框为空且不编辑文本时返回父层；
- Escape 取消当前运行或关闭 Modal，并恢复 opener 焦点；
- 当前路径和列表使用可读 label；
- 高亮使用 `aria-selected`，运行状态使用 `role="status"` 和 `aria-live="polite"`；
- 进度条使用准确的本轮 `max=20000` 和已检查值，不声明全库百分比；
- 冲突、未完整和错误不只依赖颜色；
- 中英文翻译键、插值参数、ARIA 文案和数字格式保持一致。

## 13. 测试与验收

### 13.1 浏览服务单元测试

- 固定预算被冻结且等于 20,000 条、20 请求、120 秒；
- 每个 source 调用固定传入 `limit=1000`；
- 20 个完整页后停止，不发第 21 个请求；
- 第 20,001 条不会在本轮进入缓存；
- 少于 1,000 条时标记当前层完整；
- 正好 1,000 条时保持可继续状态；
- 继续加载从准确 `nextStart` 开始；
- 失败请求计数但不推进游标；
- 文件条目经过校验后丢弃，只有目录进入快照；
- 发现子目录不自动请求子目录；
- 无效页、重复路径和身份冲突不产生半缓存；
- 取消、时间上限、网络失败和迟到响应保持页原子；
- `/` 只可作为 browser 内部路径，不能形成选择结果。

### 13.2 选择与匹配单元测试

- 扫描用途永远返回 `kind: "directory"`；
- 选择父目录时 `selectedPath === effectiveRoot`；
- 唯一 group 路径匹配返回 category、父路径和准确 `groupKey`；
- 零匹配和多匹配不使用 category 语义；
- category 选择不调用其内部 `listDirectory`；
- category 选择把核验分类收窄为唯一 group；
- 父目录选择保留合法的多分类选择；
- `/`、控制字符、非规范化路径和父级逃逸均拒绝。

### 13.3 UI 测试

- 空路径可以打开选择器；
- 打开、搜索和最近目录视图的百度调用为零；
- 每个插件会话第一次根浏览要求确认，第二次不重复；
- 插件 reload 后重新要求根确认；
- 取消根确认不改变结果或发请求；
- 面包屑只导航已进入祖先；
- 文件夹“进入”和“选择”是两个可区分动作；
- 根路径没有可用选择动作；
- 部分层显示“尚未完整”和“继续加载本层”；
- 主进度、运行详情、请求数、游标和停止原因准确；
- 空目录、陈旧最近路径、授权失败、限流、冲突和无效响应使用固定文案；
- 快速切换目录、重复点击、关闭 Modal 和 dispose 后迟到响应不修改 DOM；
- 键盘导航、焦点恢复、ARIA 状态、长路径和窄窗口可用。

### 13.4 性能测试

- 合成当前层包含 20,000 个目录时，DOM 行数保持有界；
- 可滚动访问最后一条且不丢结果；
- 20,000 条混合文件／目录输入不保留文件对象；
- 连续进入和返回多个目录后，旧监听器和临时 DOM 被释放；
- 与现有 70,000 目录索引共同存在时，不引入全量复制或第二份云端树；
- 多插件环境下的 renderer 压力门禁不得回退已完成的索引压缩成果。

### 13.5 集成与组合测试

- normal composition 只创建一个共享 source 和 browser factory；
- normal picker 同时获得本地 candidates、browser 和可选 locator；
- offline／disabled／acceptance composition 不暴露 browser；
- 设置页扫描入口和工作台核验入口共享浏览语义，但 purpose 不同；
- 选择器返回后扫描／核验调用计数仍为零；
- 外层确认后才允许调用现有核验 runtime；
- 根 browser 内部入口不能泄漏到 scan 或 verification；
- locale 切换不丢当前路径、已提交层、选择和停止状态；
- 移除凭据会清理 browser 缓存并中止运行。

### 13.6 回归与真实验收门禁

开发回归包括：

- 相关定向测试；
- 完整串行测试；
- TypeScript；
- ESLint；
- normal build；
- acceptance build；
- bundle 扫描确认 acceptance 不包含 browser、OAuth、SecretStorage 或百度列表能力。

自动测试全部使用合成 source，不发送真实百度请求。真实验收需要新的明确授权，并满足：

- 先备份插件数据和启用列表；
- 只使用一个不敏感、非根小目录；
- 不发送路径、AppKey、SecretKey、Token 或授权码到聊天；
- 不下载 PDF、不写入笔记、不修改网盘；
- 完成后恢复原插件启用状态；
- 真实请求数和停止原因必须可核对。

## 15. 已确认决策摘要

- 默认打开最近目录，单独提供“从网盘根目录浏览”；
- 每个 Obsidian 会话第一次根浏览确认一次；
- 采用面包屑、逐层进入和底部选择操作；
- 父目录和分类目录均可选择；
- 分类目录唯一匹配时自动换算并显示实际核验父目录；
- 选择分类目录只核验该分类，不读取分类内部内容；
- 采用单层按需浏览，不采用 BFS 预加载或系统原生选择框；
- 每轮上限为 20,000 条目录项，底层最多 20 次、每次 1,000 条请求；
- 20,000 条只代表网络检查预算，结果列表必须有界渲染；
- 未完整层显式显示状态并由用户点击继续；
- 根路径永不可选，选择目录不会自动开始核验；
- 不递归、不下载 PDF、不写笔记、不修改真实 Vault。
